01 · Overview

A gated pipeline, not a single collision test

Navigation is checked twice by independent data sources and again against the units C:MO actually created. A failed preflight cannot accidentally fall through into the build.

01Author

Starts and intended waypoints live in the Python scenario definition.

02Plan & repair

Natural Earth coastlines and local hazards detect and reroute unsafe legs.

03CMO preflight

The simulation engine samples terrain and water depth before any unit is built.

04Build gate

build.lua proceeds only when the preflight key is explicitly true.

05Validate

Actual assigned courses, waypoint counts, GUIDs and DBIDs are inspected.

06Save & reload

The saved .scen is reopened and validation runs against disk state.

02 · Authority

Planning geometry proposes. C:MO terrain disposes.

The offline layer makes generation deterministic and repairable. The engine layer is the final answer because it uses the terrain database that will govern the scenario.

Planning authority

Natural Earth + hazards

A clipped 1:10m land dataset provides polygon and coastline geometry. A separate hazard file adds conservative envelopes around reefs, shoals and artificial islands.

  • Fast enough to evaluate and repair every generated route.
  • Finds exact segment/coast intersections.
  • Provides clearance measurements and detour geometry.
→
Final authority

C:MO’s own elevation model

World_GetElevation evaluates sampled points inside a fresh DB3K scenario. It confirms that routes are navigable according to C:MO—not merely according to the external map.

  • Surface routes reject all elevations at or above sea level.
  • Submarine routes additionally require 200 m water depth.
  • The build is gated on an all-clear result.
03 · Offline gate

Detect, move, detour, simplify, recheck

tools/navigation.py turns raw land polygons into an indexed navigation model. resolve_navigation_routes() in the generator applies it before Lua is emitted.

Validate every unit start

All surface and submarine spawn points are checked for land and named hazard containment before a route is considered.

Reject bad waypoints

Each authored point is tested against land polygons and conservative hazard envelopes.

Intersect every route leg

Each great-circle leg is checked for exact crossings against indexed coastline segments, catching narrow islands between waypoints.

Densify and measure clearance

Great-circle interpolation samples the route at 0.25 nm. Nearest-coast distance is compared with the route-type safety margin.

0.25 nm

Repair the unsafe geometry

Unsafe waypoints are relocated to water; candidate detours are inserted around the failing coast or hazard and scored for safety and added distance.

iterative

Simplify only when safe

Unnecessary repair points are removed only if the shortened leg still passes every intersection, hazard and clearance test.

safe simplify

Revalidate the complete result

The entire repaired route is tested again. Generation stops if no safe route can be found within the bounded repair attempts.

Land intersections and configured hazards are always failures, even if sampled clearance appears acceptable elsewhere.

The offline model protects horizontal clearance; C:MO preflight supplies the decisive bathymetric depth test.

04 · Engine gate

Preflight happens before physical generation

preflight.lua runs in a fresh blank scenario using DB3K_515. It recreates each route’s great-circle track with C:MO functions and asks the engine for elevation every 0.5 nm.

Geometry

Engine-native track sampling

Tool_Bearing calculates the leg bearing. World_GetPointFromBearing advances each sample along the same spherical geometry C:MO understands.

Terrain

Elevation is queried in C:MO

World_GetElevation returns elevation at each sample. Surface and submarine rules are evaluated independently and failures retain route and location context.

Failure behavior

No partial approval

Every failure is printed. The script reports its total and withholds the preflight key unless the count is exactly zero.

Execution

Separated for console reliability

Preflight and build are separate scripts so the expensive terrain sweep completes within C:MO’s interactive console execution constraints before construction begins.

Conceptual gate logicpreflight.lua → build.lua
surface failure  = elevation >= 0
submarine failure = elevation >= 0 or water_depth < 200

if failure_count == 0 then
    ScenEdit_SetKeyValue("dc.navigation.preflight", "true")
end

-- build.lua fails closed:
if ScenEdit_GetKeyValue("dc.navigation.preflight") ~= "true" then
    error("Navigation preflight has not passed")
end

08 · Scope

What the checks guarantee—and what they do not

The framework is intentionally strict about the generated initial state. It does not claim to be a runtime navigation controller.

Covered

Generated navigation state

  • Declared surface and submarine starting positions.
  • Every generated initial route leg and waypoint.
  • Coast intersections, named hazards and clearance.
  • C:MO terrain and submarine water-depth constraints.
  • Actual built courses and persisted saved-file state.
Not covered

Routes changed during play

  • Player-created or manually edited courses after generation.
  • AI, mission logic or event scripts that later reroute a unit.
  • Navigation safety outside the generated scenario’s initial state.
  • Chart-grade coastal detail from Natural Earth alone—hence the required C:MO corroboration.
